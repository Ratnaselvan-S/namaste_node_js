Event loop
------------
    -> it has certain phases
    -> see the image for the phases
    -> the first phase is timer , the event loop when start it checks any timer callback function is available 
    -> the second phase is poll , we are making api call , i/o,file read all these are executes in second phase
    -> in thirdphase , check phase setimmediate function callback will be executed here
    -> in fourth phase, close phase here we close any ongoinge thing like socket etc
    -> each phase has separate callback queues

    -> it starts at the timer phase and one full round is completed and all the timer, check all executed ,now after one round the event loop waits in poll phase

        -> Before execution of *each* four phases, we will check two important checks that is process.nextTick() and promise callbacks

Thread
--------
    -> A thread pool is a set of CPU-executed worker threads inside the same Node.js process where heavy or blocking operations are offloaded. 
    Because of this, even though JavaScript runs on a single main thread, Node.js achieves non-blocking I/O using libuv and its thread pool (and OS async APIs).
